Code Review · Request Layer · 22 Jul 2026

Existing project review — through the lens of requests

What the current Fabric Simulator actually calls over the network, read from the code, and what each request means for the multi-tenant migration. Every finding is anchored to a file and line.

Verdict: better-positioned than a typical demo — every asset already funnels through one proxy, and the AI endpoints are clean. But the request layer has zero identity and one runtime dependency (PolyHaven) that specifically hurts live consultations. This is a wrap-and-scope job, not a rebuild.

03

Review findings

Strengths — these de-risk the migration

Single asset choke point strong

Every GLB and texture routes through /api/s3proxy. Tenant-scoping is a one-place change, not a scattered hunt — the biggest structural advantage the code has.

catalog.js:13 · all three.js loaders
AI endpoints already cleanly isolated strong

Four Gemini calls sit behind tidy /api/ handlers with clear request/response. Adding auth + metering is a wrapper, not a rewrite.

Payload & degradation handled maturely strong

Already compresses images under Vercel's 4.5MB limit and HEAD-probes endpoints for graceful fallback. Not demo-grade sloppiness.

render.js:449 _vimrCompressImage · finder.js:289 _checkEndpoint

Risks — ranked

Zero authentication on any request critical

No Authorization header anywhere in src/ (verified). Multi-tenant means adding the session token to all five request families and verifying server-side — bounded, but it touches every fetch site.

The catalog is not a request critical

Products/fabrics are a compile-time import from catalog.js, not fetched. The one request that unlocks multi-tenancy — GET /api/catalog — doesn't exist. Its exact insertion point is the hardcoded loadModel(CHAIR_GLB) call in boot.

boot.js · loadModel(CHAIR_GLB)
PolyHaven is a live consultation dependency high

Direct browser call to api.polyhaven.com. Bypasses the tenant boundary, degrades the demo if PolyHaven is slow/down, and can't be cached. Fix: bake resolved PBR maps into the tenant's S3 at onboarding; drop the runtime call.

engine.js:233 getPolyMaps
Nine silent asset failures high

.catch(() => null) swallows load errors (7 in materials.js, 2 in room.js). A fabric that fails becomes a blank grey mesh with no signal — embarrassing in front of a customer. Surface with a placeholder + toast.

materials.js ×7 · room.js ×2
Boot depends on 5 public CDN scripts medium

Three.js addons (jsdelivr) + DRACO decoder (gstatic) load at boot. For a dedicated hosted client experience, self-host them so a CDN hiccup can't blank the app mid-consultation.

boot.js · viewport.js:458
